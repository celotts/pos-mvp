# POS RAG API

A modern and containerized API for a Point of Sale (POS) system, powered by Retrieval-Augmented Generation (RAG) capabilities. Built with Python, FastAPI, and Docker, following software development best practices.

## Main Features

* **Modern API**: Built with FastAPI, offering high performance and automatic interactive documentation (Swagger UI and ReDoc).
* **Containerized Environment**: Fully managed with Docker and Docker Compose for a consistent and reproducible development and deployment environment.
* **Vector Database**: Uses PostgreSQL with the `pgvector` extension for efficient similarity searches, the foundation for the RAG system.
* **Clean Architecture**: Follows a clear separation of responsibilities (API, Business Logic, Data Access, Models, and Schemas).
* **Optimized Development Workflow**: Includes a `Makefile` with commands to simplify the most common tasks in the development lifecycle.
* **CRUD Operations**: Complete implementation of CRUD endpoints to manage the main entities of the application.

## Technologies Used

* **Backend**: Python 3.11, FastAPI
* **Database**: PostgreSQL 16, PGVector
* **Containerization**: Docker, Docker Compose
* **ORM**: SQLAlchemy
* **Data Validation**: Pydantic
* **Development Tools**: Make, Uvicorn

## 🚀 Architecture and Project Flow

```text
[HTTP Client] 
      │
      ▼ (HTTP Request)
   ┌──────┐
   │ api/ │ ◄── Validated by ─── [ schemas/ ]
   └──┬───┘
      │ (Calls)
      ▼
┌──────────┐
│ modules/ │ (Executes business logic)
└─────┬────┘
      │ (Queries/Saves)
      ▼
  ┌─────────┐
  │ models/ │ ◄── Connection via ── [ core/db.py ]
  └─────────┘
```

### Layer Responsibilities

* ⚙️ **`core/` — Configuration and Base Infrastructure:** Contains all the cross-cutting, reusable code that supports the application (environment variables, DB connection, security, base CRUD logic). It does not contain specific business logic.
* 🗄️ **`models/` — Persistence and Database:** Defines the database entities and tables mapped via SQLAlchemy.
* 📝 **`schemas/` — Validation and DTOs (Data Transfer Objects):** Defines the input and output contracts using Pydantic. It validates data for HTTP requests and responses.
* 🧠 **`modules/` — Business Logic (Services):** Groups the system's business rules. This is where the application's "know-how" lives, orchestrating operations between the API and the database.
* 🌐 **`api/` — Transport Layer and Endpoints:** Represents the HTTP interface. It receives requests, handles dependencies, and delegates execution to the corresponding service in the `modules` layer.

## Getting Started

Follow these steps to set up the local development environment.

### Prerequisites

* Docker
* Docker Compose
* `make` (usually pre-installed on Linux and macOS)

### 1. Clone the Repository

```sh
git clone <YOUR_REPOSITORY_URL>
cd pos-mvp
```

### 2. Configure Environment Variables

Create a `.env` file from the example template and adjust it if necessary.

```sh
cp .env.example .env
```

### 3. Start the Containers

Use the `make` command to build the images and start all services (API and database).

```sh
make up
```

The API service will be available at `http://localhost:8002`.

## API Documentation

Once the application is running, you can access the interactive documentation automatically generated by FastAPI at the following URLs:

* **Swagger UI**: <http://localhost:8002/docs>
* **ReDoc**: <http://localhost:8002/redoc>

## Development Commands (`Makefile`)

To facilitate development, the following commands have been defined:

* `make up`: Starts and rebuilds the containers in the background.
* `make down`: Stops and removes containers, networks, and volumes.
* `make start`: Runs `down` and then `up` for a clean restart.
* `make logs`: Shows the logs of the containers in real time.
* `make shell`: Starts a shell session (`/bin/sh`) inside the API container.
* `make format`: Automatically formats the code with `black` and `isort`.
* `make lint`: Runs the `flake8` linter to check code quality.
* `make clean`: Stops everything and cleans the system of Docker artifacts.
